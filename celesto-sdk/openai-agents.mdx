title: "OpenAI Agents sandboxes"
description: "Give an OpenAI SandboxAgent its own computer with Celesto cloud sandboxes or local SmolVM sandboxes."
---

The OpenAI Agents integration lets an OpenAI agent do its work on a separate computer that you control. The agent can run commands, read and write files, and create artifacts in that computer instead of your own machine.

You pick where the computer lives:

- **Hosted Celesto computer** &mdash; a cloud sandbox managed by Celesto. Best for production, long-running work, or running many agents at once.
- **Local SmolVM sandbox** &mdash; a sandbox that runs on your own machine. Best for development and offline use.

Both options plug into the same `SandboxAgent` workflow from the OpenAI Agents SDK, so you can swap one for the other without changing your agent code.

## When to use this

Use the OpenAI Agents sandboxes integration when you want an OpenAI agent to:

- Run shell commands or scripts in a clean environment.
- Create files the agent can come back to in a later turn.
- Try untrusted code generated by a model without touching your laptop or server.
- Save and resume an agent's workspace across sessions.

If you only need a one-off shell tool inside an agent, the simpler [SmolVM tool pattern](/smolvm/guides/ai-agent-integration#openai-agents-sdk) may be enough.

## Installation

Install the optional `openai-agents` extra. This adds the OpenAI Agents SDK and SmolVM as dependencies.

```bash
pip install "celesto[openai-agents]"
```

<Note>
  The integration requires Python 3.10 or newer. You also need an `OPENAI_API_KEY` for the agent's model and, for hosted sandboxes, a `CELESTO_API_KEY`.
</Note>

## Quickstart with a hosted Celesto computer

This example creates a fresh Celesto computer, runs an OpenAI `SandboxAgent` on it, and deletes the computer when the agent finishes.

```python
import asyncio

from agents import Runner
from agents.run import RunConfig
from agents.sandbox import SandboxAgent, SandboxRunConfig
from celesto.integrations.openai_agents import (
    CelestoSandboxClient,
    CelestoSandboxClientOptions,
)


async def main() -> None:
    agent = SandboxAgent(
        name="Workspace analyst",
        instructions="Inspect the sandbox workspace before answering.",
    )

    client = CelestoSandboxClient()
    session = await client.create(
        options=CelestoSandboxClientOptions(cpus=2, memory=2048)
    )

    try:
        async with session:
            result = await Runner.run(
                agent,
                "Run `uname -a` in the sandbox and summarize the result.",
                run_config=RunConfig(sandbox=SandboxRunConfig(session=session)),
            )
            print(result.final_output)
    finally:
        await client.delete(session)


asyncio.run(main())
```

What this does:

1. `CelestoSandboxClient()` connects to Celesto using your `CELESTO_API_KEY`.
2. `client.create(...)` reserves a new computer with the CPUs and memory you ask for.
3. `async with session:` starts the computer and prepares the agent's workspace inside it.
4. `Runner.run(...)` runs the agent. Any commands it executes go to the Celesto computer.
5. `client.delete(session)` shuts the computer down and removes it.

<Tip>
  Pass an existing `computer_id` in `CelestoSandboxClientOptions` to reuse a computer you already created. Set `delete_on_close=False` if you want to keep that computer after the session ends.
</Tip>

## Quickstart with a local SmolVM sandbox

Switch to a SmolVM sandbox by changing two imports. Everything else stays the same.

```python
import asyncio

from agents import Runner
from agents.run import RunConfig
from agents.sandbox import SandboxAgent, SandboxRunConfig
from celesto.integrations.openai_agents import (
    SmolVMSandboxClient,
    SmolVMSandboxClientOptions,
)


async def main() -> None:
    agent = SandboxAgent(
        name="Workspace analyst",
        instructions="Inspect the sandbox workspace before answering.",
    )

    client = SmolVMSandboxClient()
    session = await client.create(
        options=SmolVMSandboxClientOptions(memory=2048, disk_size=4096)
    )

    try:
        async with session:
            result = await Runner.run(
                agent,
                "Run `uname -a` in the sandbox and summarize the result.",
                run_config=RunConfig(sandbox=SandboxRunConfig(session=session)),
            )
            print(result.final_output)
    finally:
        await client.delete(session)


asyncio.run(main())
```

SmolVM creates a small virtual machine on your own machine. It is a good fit for local development because there is no network round trip and no cloud cost.

## Choosing between hosted and local

| | **Hosted (Celesto)** | **Local (SmolVM)** |
| --- | --- | --- |
| Runs on | Celesto cloud | Your machine |
| Boot time | Seconds | Milliseconds |
| Needs an API key | Yes (`CELESTO_API_KEY`) | No |
| Good for | Production, parallel agents, long jobs | Development, offline work, fast loops |
| Resume later from another machine | Yes | Limited to the same host |

Both clients share the same interface, so you can keep your agent code and switch the client based on the environment.

## Configuration

### CelestoSandboxClientOptions

Settings for hosted Celesto computers.

<ParamField path="cpus" type="integer" default="1">
  Number of virtual CPUs for the computer. Range: 1&ndash;16.
</ParamField>

<ParamField path="memory" type="integer" default="1024">
  Memory in MB. Range: 512&ndash;32768.
</ParamField>

<ParamField path="image" type="string" default="ubuntu-desktop-24.04">
  OS image to use. See [Computers API](/celesto-sdk/overview#create-a-computer) for the full list.
</ParamField>

<ParamField path="computer_id" type="string">
  ID of an existing Celesto computer. If you set this, the client uses that computer instead of creating a new one.
</ParamField>

<ParamField path="delete_on_close" type="boolean">
  Whether to delete the computer when the session ends. Defaults to `true` when the client created the computer, and `false` when you supplied a `computer_id`.
</ParamField>

### SmolVMSandboxClientOptions

Settings for local SmolVM sandboxes.

<ParamField path="memory" type="integer">
  Memory in MB for the local VM. Defaults to SmolVM's built-in default.
</ParamField>

<ParamField path="disk_size" type="integer">
  Disk size in MB for the local VM.
</ParamField>

<ParamField path="os" type="string">
  Operating system for the local VM. See [SmolVM custom images](/smolvm/guides/custom-images) for the available options.
</ParamField>

<ParamField path="backend" type="string">
  SmolVM backend to use. See [SmolVM backends](/smolvm/concepts/backends).
</ParamField>

<ParamField path="exposed_ports" type="array">
  Ports inside the VM to expose to your host machine.
</ParamField>

<ParamField path="vm_id" type="string">
  ID of an existing SmolVM. If set, the client connects to that VM instead of creating a new one.
</ParamField>

<ParamField path="delete_on_close" type="boolean">
  Whether to delete the VM when the session ends. Defaults to `true` when the client created the VM, and `false` when you supplied a `vm_id`.
</ParamField>

## Reusing a sandbox across runs

You can save the session state, end the program, and pick up where you left off later. This is useful when an agent's work spans multiple user turns or job runs.

```python
state_payload = session.state.model_dump()  # save to disk, database, etc.

# ... later, in another process ...

restored_state = client.deserialize_session_state(state_payload)
session = await client.resume(restored_state)
async with session:
    # The sandbox is back, with the same computer and workspace files.
    ...
```

For Celesto sandboxes, the same `computer_id` is reused. For SmolVM sandboxes, the same `vm_id` is reused. In both cases set `delete_on_close=False` on the original options so the sandbox is kept around after the first run.

## Reading and writing files

Both sandbox sessions expose `read` and `write` methods for moving files in and out of the agent's workspace.

```python
from pathlib import Path
import io

async with session:
    await session.write(Path("notes.txt"), io.BytesIO(b"hello sandbox"))
    contents = await session.read(Path("notes.txt"))
    print(contents.read())
```

You can also save the entire workspace as a tarball with `persist_workspace()` and restore it later with `hydrate_workspace()`. This is the easiest way to ship the agent's working files between two different sandboxes.

## Error handling

If you forget to install the optional extra, importing the integration raises a clear `ImportError`:

```text
OpenAI Agents support is not installed. Run
`pip install 'celesto[openai-agents]'` and try again.
```

For Celesto sandboxes, network and auth errors come from the [Celesto SDK error classes](/celesto-sdk/overview#error-handling).
