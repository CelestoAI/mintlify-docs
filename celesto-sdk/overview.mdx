---

The Celesto SDK lets you create sandboxed computers, run commands inside them, and manage the full lifecycle from your code or the command line. You can use it to spin up isolated environments for AI agents, run untrusted code safely, or automate development workflows. The SDK is available for both Python and JavaScript/TypeScript.

<Note>
  Both SDKs use the same top-level class name: `Celesto`. The JavaScript SDK previously exported `CelestoClient`, which has been removed — import `Celesto` instead.
</Note>

## Installation

<CodeGroup>

```bash Python
pip install celesto
```

```bash JavaScript
npm install @celestoai/sdk
```

</CodeGroup>

## Authentication

Set your API key as an environment variable or pass it directly:

<CodeGroup>

```python Python
import os
os.environ["CELESTO_API_KEY"] = "your-api-key"
```

```bash JavaScript
export CELESTO_API_KEY="your-api-key"
```

</CodeGroup>

You can also pass the key when you create the client:

<CodeGroup>

```python Python
from celesto import Celesto

client = Celesto(api_key="your-api-key")
```

```ts JavaScript
import { Celesto } from "@celestoai/sdk";

const client = new Celesto({ token: "your-api-key" });
```

</CodeGroup>

<Tip>
  Get your API key from [celesto.ai](https://celesto.ai) under **Settings > Security**.
</Tip>

### JavaScript client options

The `Celesto` constructor accepts an optional configuration object:

<ParamField body="token" type="string">
  Celesto API key or JWT. You can also pass it as `apiKey`. If omitted, the SDK does not read the environment for you — set `process.env.CELESTO_API_KEY` and pass it explicitly.
</ParamField>

<ParamField body="organizationId" type="string">
  Organization ID to send as the `X-Current-Organization` header. Useful for JWTs that span multiple organizations.
</ParamField>

<ParamField body="baseUrl" type="string" default="https://api.celesto.ai">
  Override the API base URL (for example, to point at a staging environment).
</ParamField>

<ParamField body="timeoutMs" type="number">
  Default request timeout in milliseconds. Individual calls can still pass their own `timeout`.
</ParamField>

<Note>
  The JavaScript SDK requires Node 18 or newer for the built-in `fetch`. It has zero runtime dependencies.
</Note>

## Quick example

<CodeGroup>

```python Python
from celesto import Celesto

with Celesto() as client:
    computer = client.computers.create(cpus=2, memory=2048)
    print(f"Computer ready: {computer['name']}")

    result = client.computers.exec(computer["id"], "uname -a")
    print(result["stdout"])

    client.computers.delete(computer["id"])
```

```ts JavaScript
import { Celesto } from "@celestoai/sdk";

const client = new Celesto({ token: process.env.CELESTO_API_KEY });

const computer = await client.computers.create({ cpus: 2, memory: 2048 });
console.log(`Computer ready: ${computer.name}`);

const result = await client.computers.exec(computer.id, "uname -a");
console.log(result.stdout);

await client.computers.delete(computer.id);
```

</CodeGroup>

## Computers API

The Computers API lets you create, manage, and interact with sandboxed virtual machines.

### Create a computer

<CodeGroup>

```python Python
computer = client.computers.create(cpus=2, memory=2048)
print(computer["name"])   # e.g., "einstein"
print(computer["id"])     # e.g., "cmp_abc123"
print(computer["status"]) # "creating" or "running"
```

```ts JavaScript
const computer = await client.computers.create({ cpus: 2, memory: 2048 });
console.log(computer.name);   // e.g., "einstein"
console.log(computer.id);     // e.g., "cmp_abc123"
console.log(computer.status); // "creating" or "running"
```

</CodeGroup>

<ParamField body="cpus" type="integer" default="1">
  Number of virtual CPUs. Range: 1-16.
</ParamField>

<ParamField body="memory" type="integer" default="1024">
  Memory in MB. Range: 512-32768.
</ParamField>

<ParamField body="image" type="string" default="ubuntu-desktop-24.04">
  OS image to use for the computer.
</ParamField>

The response includes these fields:

<ResponseField name="id" type="string" required>
  Unique identifier for the computer (e.g., `cmp_abc123`).
</ResponseField>

<ResponseField name="name" type="string" required>
  Auto-generated display name for the computer (e.g., `einstein`).
</ResponseField>

<ResponseField name="status" type="string" required>
  Current status. One of: `creating`, `running`, `stopping`, `stopped`, `starting`, `deleting`, `deleted`, `error`.
</ResponseField>

<ResponseField name="vcpus" type="integer" required>
  Number of virtual CPUs allocated.
</ResponseField>

<ResponseField name="ram_mb" type="integer" required>
  Memory allocated in MB.
</ResponseField>

<ResponseField name="image" type="string" required>
  OS image used.
</ResponseField>

<ResponseField name="created_at" type="string" required>
  ISO 8601 timestamp of when the computer was created.
</ResponseField>

<ResponseField name="stopped_at" type="string">
  ISO 8601 timestamp of when the computer was stopped. Only present if the computer has been stopped.
</ResponseField>

<ResponseField name="last_error" type="string">
  Description of the most recent error, if the computer is in `error` status.
</ResponseField>

<ResponseField name="connection" type="object">
  Connection details for accessing a running computer.

  <Expandable title="Connection properties">
    <ResponseField name="ssh" type="string">
      SSH connection string for terminal access.
    </ResponseField>

    <ResponseField name="access_url" type="string">
      URL for browser-based access to the computer.
    </ResponseField>
  </Expandable>
</ResponseField>

### Execute commands

Run a shell command on a computer:

<CodeGroup>

```python Python
result = client.computers.exec(computer["id"], "ls -la /home")
print(result["stdout"])
print(result["exit_code"])
```

```ts JavaScript
const result = await client.computers.exec(computer.id, "ls -la /home");
console.log(result.stdout);
console.log(result.exitCode);
```

</CodeGroup>

<ParamField body="computer_id" type="string" required>
  Computer ID or name.
</ParamField>

<ParamField body="command" type="string" required>
  Shell command to execute.
</ParamField>

<ParamField body="timeout" type="integer" default="30">
  Timeout in seconds. Range: 1-300.
</ParamField>

The response includes:

<ResponseField name="exit_code" type="integer" required>
  Exit code of the command. `0` means success.
</ResponseField>

<ResponseField name="stdout" type="string" required>
  Standard output from the command.
</ResponseField>

<ResponseField name="stderr" type="string" required>
  Standard error output from the command.
</ResponseField>

### Get a computer

Retrieve details of a specific computer:

<CodeGroup>

```python Python
info = client.computers.get(computer["id"])

```

```ts JavaScript
const info = await client.computers.get(computer.id);
console.log(`${info.name}: ${info.status}`);
```

</CodeGroup>

### List computers

<CodeGroup>

```python Python
result = client.computers.list()
for vm in result["computers"]:
    print(f"{vm['name']}: {vm['status']}")
print(f"Total: {result['count']}")
```

```ts JavaScript
const result = await client.computers.list();
for (const vm of result.computers) {
  console.log(`${vm.name}: ${vm.status}`);
}
console.log(`Total: ${result.count}`);
```

</CodeGroup>

The response includes:

<ResponseField name="computers" type="array" required>
  List of computer objects, each with the same fields as the create response.
</ResponseField>

<ResponseField name="count" type="integer" required>
  Total number of computers in the list.
</ResponseField>

### Terminal connection (JavaScript only)

The JavaScript SDK provides a `getTerminalConnection` method that returns the URL, headers, and first message you need to open an interactive WebSocket terminal session. Bring your own WebSocket library — the SDK has zero runtime dependencies, so you can use [`ws`](https://www.npmjs.com/package/ws), Node's built-in WebSocket (Node 22+), or any other client.

<Warning>
  Earlier versions exposed `openTerminal()` and a `Terminal` class backed by the `ws` package. Both were removed. Replace them with `getTerminalConnection()` and the WebSocket library of your choice.
</Warning>

<Note>
  `getTerminalConnection()` does not auto-resume a stopped computer. Call `start()` and wait for `status === "running"` before opening the connection.
</Note>

```ts
import WebSocket from "ws";

const conn = await client.computers.getTerminalConnection("my-computer");
const ws = new WebSocket(conn.url, { headers: conn.headers });
ws.on("open", () => ws.send(conn.firstMessage));
ws.on("message", (data) => process.stdout.write(data));
```

The method accepts either a computer ID (e.g., `cmp_abc123`) or a human-readable name. It resolves the name to the canonical ID before the handshake.

<ResponseField name="url" type="string" required>
  The `wss://` URL for the WebSocket connection.
</ResponseField>

<ResponseField name="headers" type="object" required>
  Headers to include in the WebSocket handshake, including the `Authorization` header.
</ResponseField>

<ResponseField name="firstMessage" type="string" required>
  JSON string to send as the first message after connecting.
</ResponseField>

## CLI reference

The `celesto` CLI focuses on computer management. All commands live under `celesto computer`.

| Command | Description |
|---|---|
| `celesto computer create [--cpus N] [--memory MB]` | Create a computer |
| `celesto computer list` | List all computers |
| `celesto computer run <name> "command"` | Execute a command (auto-resumes stopped computers) |
| `celesto computer ssh <name>` | Interactive terminal (auto-resumes stopped computers) |
| `celesto computer stop <name>` | Stop a computer |
| `celesto computer start <name>` | Start a stopped computer |
| `celesto computer delete <name> [--force]` | Delete a computer |

You can use either the computer name or ID for any command that takes a computer identifier.

### Auto-resume

The `run` and `ssh` commands automatically resume a stopped computer before executing. If you run a command or open a terminal session on a stopped computer, the CLI starts it, waits for it to become available, and then proceeds. You do not need to call `start` manually first.

```bash
# This works even if "einstein" is stopped
celesto computer run einstein "uname -a"

# Opens a terminal, resuming the computer if needed
celesto computer ssh einstein
```

### JSON output

All commands support `--json` (`-j`) for machine-readable output, which is useful for scripting and AI agent integrations:

```bash
celesto computer list --json
celesto computer create --cpus 2 --memory 2048 --json
celesto computer run einstein "uname -a" --json
```

### Examples

Create a computer and run a command:

```bash
export CELESTO_API_KEY="your-api-key"

celesto computer create --cpus 2 --memory 2048
celesto computer run einstein "ls -la"
celesto computer ssh einstein
celesto computer delete einstein
```

## Deployment API

The Deployment API lets you package and deploy AI agents to Celesto's managed infrastructure.

### Deploy an agent

<Note>
  The Deployment API is currently available in the Python SDK only.
</Note>

```python
from pathlib import Path

result = client.deployment.deploy(
    folder=Path("./my-agent"),
    name="weather-agent-v1",
    description="Weather assistant",
    envs={"OPENAI_API_KEY": "sk-..."}
)

print(f"Deployment ID: {result['id']}")
print(f"Status: {result['status']}")
```

<ParamField body="folder" type="Path" required>
  Path to the directory containing your agent code.
</ParamField>

<ParamField body="name" type="string" required>
  Unique name for the deployment.
</ParamField>

<ParamField body="description" type="string">
  Human-readable description of the deployment.
</ParamField>

<ParamField body="envs" type="object">
  Environment variables as key-value pairs.
</ParamField>

<ParamField body="project_name" type="string">
  Project name to scope the deployment. Defaults to your first project.
</ParamField>

The response includes:

<ResponseField name="id" type="string" required>
  Unique deployment identifier.
</ResponseField>

<ResponseField name="status" type="string" required>
  Deployment status: `BUILDING`, `READY`, or `FAILED`.
</ResponseField>

<ResponseField name="url" type="string">
  Endpoint URL, available when status is `READY`.
</ResponseField>

<ResponseField name="message" type="string">
  Additional information about the deployment result.
</ResponseField>

### List deployments

```python
deployments = client.deployment.list()
for dep in deployments:
    print(f"{dep['name']}: {dep['status']}")
```

Each deployment object in the list includes:

<ResponseField name="id" type="string" required>
  Unique deployment identifier.
</ResponseField>

<ResponseField name="name" type="string" required>
  Deployment name.
</ResponseField>

<ResponseField name="description" type="string">
  Human-readable description, if provided during deploy.
</ResponseField>

<ResponseField name="status" type="string" required>
  Deployment status: `READY`, `BUILDING`, `FAILED`, or `STOPPED`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the deployment was created.
</ResponseField>

<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp of the most recent update.
</ResponseField>

## Error handling

Both SDKs provide typed errors so you can handle different failure modes.

<Tabs>
  <Tab title="Python">
    ```python
    from celesto.sdk.exceptions import (
        CelestoAuthenticationError,
        CelestoValidationError,
        CelestoNotFoundError,
        CelestoRateLimitError,
        CelestoServerError,
        CelestoNetworkError,
    )
    ```

    | Exception | When it occurs |
    |---|---|
    | `CelestoAuthenticationError` | Invalid or missing API key (401/403) |
    | `CelestoValidationError` | Invalid parameters (400/422) |
    | `CelestoNotFoundError` | Resource not found (404) |
    | `CelestoRateLimitError` | Too many requests (429) |
    | `CelestoServerError` | Server-side error (5xx) |
    | `CelestoNetworkError` | Connection failures or timeouts |
  </Tab>
  <Tab title="JavaScript">
    ```ts
    import { CelestoError, CelestoApiError, CelestoNetworkError } from "@celestoai/sdk";

    try {
      await client.computers.get("missing-name");
    } catch (err) {
      if (err instanceof CelestoApiError) {
        console.error(`API ${err.status}:`, err.data);
      } else if (err instanceof CelestoNetworkError) {
        console.error("Network error:", err.cause);
      } else if (err instanceof CelestoError) {
        console.error("SDK error:", err.message);
      }
    }
    ```

    | Error class | Extends | When it occurs |
    |---|---|---|
    | `CelestoApiError` | `CelestoError` | Any non-2xx HTTP response. Inspect `.status` (HTTP code), `.data` (parsed body), and `.requestId`. |
    | `CelestoNetworkError` | `CelestoError` | DNS failures, timeouts, or connection errors. Inspect `.cause` for the underlying `Error`. |
    | `CelestoError` | `Error` | Base class. Catch this to handle any SDK error. |

    <Note>
      Network failures from `fetch()` (DNS, offline, timeout) are wrapped as `CelestoNetworkError` instead of leaking raw `TypeError`. Catch `CelestoError` to handle both API and network errors with one branch.
    </Note>
  </Tab>
</Tabs>
