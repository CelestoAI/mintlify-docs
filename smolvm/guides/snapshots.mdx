---
title: "Snapshots"
description: "Save and restore sandbox disk or runtime state so you can recover later"
---

Snapshots let you save a sandbox and restore it later. Use them when you want to checkpoint work, retry a risky step, or preserve a configured environment without rebuilding it.

## Snapshot types

SmolVM supports three snapshot types.

| Type | What it stores | Restore behavior | Best for |
| --- | --- | --- | --- |
| `"full"` | Self-contained disk plus runtime state when the backend supports it | Restores without depending on the original base image | General checkpoints |
| `"diff"` | Changed disk data relative to the base image | Depends on the original base image staying present | Smaller local snapshots |
| `"disk"` | Self-contained disk only on QEMU | Boots fresh from the saved disk instead of resuming memory | Suspend/restore across hosts, filesystem checkpoints |

<Note>
  QEMU disk snapshots with `snapshot_type="disk"` skip the guest RAM dump. That makes them faster and smaller, but restore starts as a cold boot from the saved disk.
</Note>

## Create a snapshot

To create a snapshot, the VM must be running or paused. SmolVM pauses the VM while it takes the snapshot.

<Tabs>
  <Tab title="Python">
    ```python  theme={null}
    from smolvm import SmolVM

    with SmolVM(backend="qemu") as vm:
        vm.run("apk add --no-cache python3")

        snapshot = vm.snapshot(
            snapshot_id="python-ready",
            snapshot_type="disk",
            resume_source=True,
        )

        print(snapshot.snapshot_id)
    ```
  </Tab>

  <Tab title="CLI">
    ```bash  theme={null}
    smolvm snapshot create my-vm \
      --snapshot-id python-ready \
      --snapshot-type disk \
      --resume-source
    ```
  </Tab>
</Tabs>

If you omit `snapshot_id`, SmolVM generates one for you.

## Choose a snapshot type

### Full snapshots

Use `"full"` when you want the most portable snapshot for normal restore workflows.

```python  theme={null}
snapshot = vm.snapshot(
    snapshot_id="before-upgrade",
    snapshot_type="full",
)
```

### Diff snapshots

Use `"diff"` when local disk usage matters and the original base image will stay available.

```python  theme={null}
snapshot = vm.snapshot(
    snapshot_id="small-checkpoint",
    snapshot_type="diff",
)
```

<Warning>
  A diff snapshot depends on its original base image. If that base image is deleted or moved, restore can fail.
</Warning>

### Disk-only snapshots

Use `"disk"` when you only need filesystem state and a fresh boot is acceptable.

```python  theme={null}
snapshot = vm.snapshot(
    snapshot_id="filesystem-state",
    snapshot_type="disk",
)
```

Disk-only snapshots are especially useful for QEMU sandboxes because they avoid saving guest RAM through QMP.

## Restore a snapshot

Restoring a snapshot recreates the original VM from the saved state.

<Tabs>
  <Tab title="Python">
    ```python  theme={null}
    from smolvm import SmolVM

    vm = SmolVM.from_snapshot("python-ready", resume_vm=True)
    print(vm.status)

    result = vm.run("python3 --version")
    print(result.output)

    vm.close()
    ```
  </Tab>

  <Tab title="CLI">
    ```bash  theme={null}
    smolvm snapshot restore python-ready --resume
    ```
  </Tab>
</Tabs>

A snapshot can only be restored once by default. Use `force=True` or `--force` when you intentionally want to restore the same snapshot again.

<Tabs>
  <Tab title="Python">
    ```python  theme={null}
    vm = SmolVM.from_snapshot("python-ready", resume_vm=True, force=True)
    ```
  </Tab>

  <Tab title="CLI">
    ```bash  theme={null}
    smolvm snapshot restore python-ready --resume --force
    ```
  </Tab>
</Tabs>

## List snapshots

<Tabs>
  <Tab title="Python">
    ```python  theme={null}
    from smolvm import SmolVMManager

    with SmolVMManager() as manager:
        snapshots = manager.list_snapshots()
        for snapshot in snapshots:
            print(snapshot.snapshot_id, snapshot.snapshot_type)
    ```
  </Tab>

  <Tab title="CLI">
    ```bash  theme={null}
    smolvm snapshot list
    ```
  </Tab>
</Tabs>

## Delete a snapshot

Deleting a snapshot removes the saved files and metadata.

<Tabs>
  <Tab title="Python">
    ```python  theme={null}
    from smolvm import SmolVMManager

    with SmolVMManager() as manager:
        manager.delete_snapshot("python-ready")
    ```
  </Tab>

  <Tab title="CLI">
    ```bash  theme={null}
    smolvm snapshot delete python-ready
    ```
  </Tab>
</Tabs>

<Warning>
  Do not delete a snapshot while a restored VM from that snapshot is still running.
</Warning>

## Backend notes

- QEMU supports disk-only snapshots that skip guest RAM and cold-boot on restore.
- QEMU full snapshots preserve runtime state inside the copied qcow2 snapshot data.
- Firecracker snapshots capture Firecracker VM state and guest memory; use `"diff"` to reduce disk copy size when the base image can stay available.
- Snapshots are not supported for VMs with workspace mounts.

## Error handling

```python  theme={null}
from smolvm import SmolVM, SnapshotNotFoundError, SmolVMError

try:
    vm = SmolVM.from_snapshot("missing-snapshot")
except SnapshotNotFoundError:
    print("Snapshot does not exist")
except SmolVMError as exc:
    print(f"Restore failed: {exc}")
```
