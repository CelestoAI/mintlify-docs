---
title: "VMConfig"
description: "Configure CPU, memory, boot mode, disk format, networking, and disk lifecycle for a SmolVM sandbox"
---

`VMConfig` is the low-level configuration model for a sandbox. Most users can start with `SmolVM(...)` or `SmolVM.from_image(...)`; use `VMConfig` when you need direct control over boot paths, disk lifecycle, or runtime backend settings.

## Model

```python  theme={null}
class VMConfig(BaseModel)
```

`VMConfig` is immutable and rejects unknown fields.

## Core fields

<ParamField path="vm_id" type="str" default="auto-generated">
  Unique sandbox ID. If omitted, SmolVM generates one.
</ParamField>

<ParamField path="vcpu_count" type="int" default="2">
  Number of virtual CPUs. Valid range: 1-32.
</ParamField>

<ParamField path="memory" type="int" default="512">
  Guest memory in MiB. Valid range: 128-16384.
</ParamField>

<ParamField path="guest_os" type="GuestOS" default="GuestOS.ALPINE">
  Guest operating system metadata.
</ParamField>

<ParamField path="backend" type="str | None" default="None">
  Runtime backend override. Options are `"firecracker"`, `"qemu"`, `"libkrun"`, or `None`.
</ParamField>

## Boot fields

<ParamField path="boot_mode" type='"direct_kernel" | "firmware"' default='"direct_kernel"'>
  How the guest boots.

  - `"direct_kernel"`: the backend loads `kernel_path` directly and passes `boot_args`.
  - `"firmware"`: QEMU boots the disk through firmware. The guest kernel lives inside `rootfs_path`.
</ParamField>

<ParamField path="kernel_path" type="Path | None" default="None">
  Kernel image path. Required for `boot_mode="direct_kernel"` and forbidden for `boot_mode="firmware"`.
</ParamField>

<ParamField path="initrd_path" type="Path | None" default="None">
  Optional initrd image path.
</ParamField>

<ParamField path="rootfs_path" type="Path" required>
  Root filesystem image path. The path must exist and point to a file.
</ParamField>

<ParamField path="rootfs_format" type='"raw-ext4" | "qcow2" | None' default="None">
  Declared root filesystem format. New configs should set this to `"raw-ext4"` or `"qcow2"`.
</ParamField>

<ParamField path="extra_drives" type="list[Path]" default="[]">
  Additional block-device image paths to attach at boot.
</ParamField>

<ParamField path="boot_args" type="str" default='"console=ttyS0 reboot=k panic=1 pci=off"'>
  Kernel command line for direct-kernel boot. Ignored in firmware mode.
</ParamField>

<ParamField path="ssh_capable" type="bool" default="False">
  Whether this boot path is expected to start SSH without relying on SmolVM auto-config.
</ParamField>

<ParamField path="ssh_public_key" type="str | None" default="None">
  OpenSSH public key to pass to SmolVM-ready images at first boot.
</ParamField>

## Disk lifecycle fields

<ParamField path="disk_mode" type='"isolated" | "shared"' default='"isolated"'>
  Disk lifecycle mode.

  - `"isolated"`: create a per-VM disk from `rootfs_path`.
  - `"shared"`: boot directly from `rootfs_path`.
</ParamField>

<ParamField path="disk_size_mib" type="int | None" default="None">
  Requested size for the isolated per-VM disk. SmolVM refuses to resize a shared base image.
</ParamField>

<ParamField path="grow_filesystem" type="bool" default="False">
  Grow the guest filesystem after resizing when supported. This currently supports raw ext4 images.
</ParamField>

<ParamField path="retain_disk_on_delete" type="bool" default="False">
  Keep the isolated VM disk after deletion so a later create with the same VM ID can reuse it.
</ParamField>

## Network and communication fields

<ParamField path="qemu_network" type='"slirp" | "tap"' default='"slirp"'>
  QEMU network mode. Ignored by non-QEMU backends.
</ParamField>

<ParamField path="port_forwards" type="list[PortForwardConfig]" default="[]">
  Host-to-guest TCP forwards configured at VM launch. Host and guest ports must be unique within the list.
</ParamField>

<ParamField path="vsock" type="VsockConfig | None" default="None">
  Optional vsock configuration.
</ParamField>

<ParamField path="comm_channel" type='"ssh" | "vsock" | None' default="None">
  Host-to-guest control channel. `None` means SmolVM auto-selects when possible.
</ParamField>

<ParamField path="internet_settings" type="InternetSettings | None" default="None">
  Internet access configuration.
</ParamField>

<ParamField path="network_rate_limit_mbps" type="int | None" default="None">
  Optional outbound network bandwidth limit in megabits per second.
</ParamField>

<ParamField path="workspace_mounts" type="list[WorkspaceMount]" default="[]">
  Workspace mounts exposed to the guest.
</ParamField>

<ParamField path="env_vars" type="dict[str, str]" default="{}">
  Environment variables to inject into the guest after boot through SSH.
</ParamField>

## Direct-kernel example

```python  theme={null}
from pathlib import Path

from smolvm import VMConfig, ensure_base_kernel_for_backend

config = VMConfig(
    vm_id="worker",
    vcpu_count=2,
    memory=1024,
    kernel_path=ensure_base_kernel_for_backend("qemu"),
    rootfs_path=Path("/var/lib/smolvm/images/worker/rootfs.ext4"),
    rootfs_format="raw-ext4",
    boot_args="console=ttyS0 reboot=k panic=1 root=/dev/vda rw init=/init",
    backend="qemu",
    ssh_capable=True,
)
```

## Firmware example

```python  theme={null}
from pathlib import Path

from smolvm import VMConfig

config = VMConfig(
    vm_id="ubuntu-cloud",
    memory=2048,
    boot_mode="firmware",
    kernel_path=None,
    rootfs_path=Path("/var/lib/smolvm/images/ubuntu.qcow2"),
    rootfs_format="qcow2",
    backend="qemu",
    ssh_capable=True,
)
```

## Resized custom image example

```python  theme={null}
from pathlib import Path

from smolvm import VMConfig, ensure_base_kernel_for_backend

config = VMConfig(
    vm_id="large-worker",
    kernel_path=ensure_base_kernel_for_backend("qemu"),
    rootfs_path=Path("/var/lib/smolvm/images/worker/rootfs.ext4"),
    rootfs_format="raw-ext4",
    boot_args="console=ttyS0 reboot=k panic=1 root=/dev/vda rw init=/init",
    backend="qemu",
    disk_mode="isolated",
    disk_size_mib=8192,
    grow_filesystem=True,
)
```

<Note>
  Prefer `SmolVM.from_image(..., disk_size_mb=..., grow_filesystem=True)` for custom images. Use `VMConfig` directly when you need lower-level control.
</Note>

## Validation rules

- `VMConfig` rejects unknown fields.
- `memory` must be between 128 and 16384 MiB.
- `vcpu_count` must be between 1 and 32.
- Direct-kernel boot requires `kernel_path`.
- Firmware boot requires `backend="qemu"` and `kernel_path=None`.
- Windows guests require firmware boot.
- `rootfs_path`, `kernel_path`, `initrd_path`, and `extra_drives` must point to files when set.
- `port_forwards` cannot reuse host or guest ports.
- `workspace_mounts` cannot reuse mount tags or guest paths.

## Disk format behavior

`rootfs_format` controls QEMU drive arguments and disk lifecycle behavior.

| Format | Use case | Resize behavior |
| --- | --- | --- |
| `"raw-ext4"` | Raw ext4 root filesystem images | SmolVM can resize the disk and grow the filesystem when `grow_filesystem=True` |
| `"qcow2"` | QEMU firmware or cloud images | SmolVM can resize virtual disk size, but it does not grow the guest filesystem |

If `rootfs_format` is omitted, SmolVM falls back to filename inference for older configs. New docs and code should set it explicitly.
