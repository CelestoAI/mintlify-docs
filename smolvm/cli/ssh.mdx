---
title: "smolvm ssh"
description: "SSH into an existing VM, auto-starting it when needed"
---

The `ssh` command opens an interactive SSH session to a SmolVM instance. If the VM is stopped or was just created, SmolVM automatically starts it before connecting.

## Synopsis

```bash
smolvm ssh <vm_id> [OPTIONS]
```

## Arguments

<ParamField path="vm_id" type="string" required>
  The identifier of the VM to connect to.
</ParamField>

## Options

<ParamField path="--ssh-key" type="string" default="~/.smolvm/keys/id_ed25519">
  SSH private key path for authentication.
</ParamField>

<ParamField path="--ssh-user" type="string" default="root">
  SSH user to connect as.
</ParamField>

<ParamField path="--boot-timeout" type="float" default="30">
  Seconds to wait for VM boot and SSH readiness if the VM needs to be started.
</ParamField>

## Examples

### Connect to a running VM

```bash
smolvm ssh my-agent
```

### Connect with custom SSH credentials

```bash
smolvm ssh my-agent --ssh-user ubuntu --ssh-key ~/.ssh/custom_key
```

### Auto-start a stopped VM

If a VM is in `created` or `stopped` state, SmolVM starts it automatically:

```bash
smolvm ssh my-agent
```

```
Notice: VM 'my-agent' isn't running yet. SSH may take a little longer while SmolVM starts it.
```

## Behavior

- **Running VMs** - Connects immediately after verifying SSH readiness.
- **Created or stopped VMs** - SmolVM starts the VM first, then connects. A notice is printed so you know to expect a short delay.
- **Error state VMs** - The command fails with a message asking you to recreate the VM or inspect its logs.

<Note>
  The `ssh` command requires the `ssh` binary (openssh-client) to be installed on your host.
</Note>

## Exit codes

| Code | Description                                 |
| ---- | ------------------------------------------- |
| `0`  | SSH session exited cleanly                  |
| `1`  | Error - VM not found, in error state, etc.  |
| Any  | Forwarded from the remote SSH session       |
