title: "smolvm snapshot"
description: "Use the smolvm snapshot CLI to create, restore, list, and delete SmolVM sandbox snapshots for checkpointing agents and retrying failed steps."
---

## Synopsis

```bash  theme={null}
smolvm snapshot {create,restore,delete,list} [OPTIONS]
```

## Description

The `snapshot` command saves a sandbox so you can restore it later. Use it to checkpoint an agent, keep a configured environment, or retry a risky step from a known state.

<Note>
  Snapshots work on Firecracker and QEMU for Linux guests with isolated disks. Windows guests, workspace mounts, and extra drives are not supported yet. QEMU snapshots require a qcow2 per-VM disk.
</Note>

## Subcommands

### create

Save a running or paused VM.

```bash  theme={null}
smolvm snapshot create <vm_id> [--snapshot-id <id>] [--snapshot-type {full,diff,disk}] [--resume-source] [--json]
```

<ParamField path="vm_id" type="string" required>
  The identifier of the VM to snapshot. The VM must be running or paused.
</ParamField>

<ParamField path="--snapshot-id" type="string">
  A custom identifier for the snapshot. If omitted, SmolVM generates one automatically (for example, `snap-my-vm-1717012345`). Must contain only lowercase letters, numbers, hyphens, and underscores.
</ParamField>

<ParamField path="--snapshot-type" type="string" default="full">
  How much state to store:

  * `full` saves a complete disk copy plus memory and CPU state.
  * `diff` saves a smaller disk artifact. QEMU diff snapshots need their backing image at restore time.
  * `disk` is disk-only on QEMU and restores with a cold boot.

  See [snapshot types](/smolvm/features/snapshots#choose-a-snapshot-type) for guidance.
</ParamField>

<ParamField path="--resume-source" type="flag">
  Resume the source VM after the snapshot is created. Without this flag, the VM stays paused.
</ParamField>

<ParamField path="--json" type="flag">
  Output machine-readable JSON instead of human-friendly text.
</ParamField>

**Example:**

```bash  theme={null}
smolvm snapshot create my-vm --snapshot-id before-deploy --resume-source
```

To create a space-saving diff snapshot:

```bash  theme={null}
smolvm snapshot create my-vm --snapshot-type diff
```

To create a QEMU disk-only snapshot:

```bash  theme={null}
smolvm snapshot create my-vm --snapshot-type disk
```

**Example output:**

```
Created snapshot 'before-deploy' from VM 'my-vm'.
```

### restore

Restore a snapshot back into its original VM identity.

```bash  theme={null}
smolvm snapshot restore <snapshot_id> [--resume] [--force] [--json]
```

<ParamField path="snapshot_id" type="string" required>
  The identifier of the snapshot to restore.
</ParamField>

<ParamField path="--resume" type="flag">
  Resume the restored VM immediately. Without this flag, the VM is restored in a paused state.
</ParamField>

<ParamField path="--force" type="flag">
  Allow restoring a snapshot that was already restored before. By default, a snapshot can only be restored once.
</ParamField>

<ParamField path="--json" type="flag">
  Output machine-readable JSON instead of human-friendly text.
</ParamField>

**Example:**

```bash  theme={null}
smolvm snapshot restore before-deploy --resume
```

**Example output:**

```
Restored snapshot 'before-deploy' into VM 'my-vm'.
```

### delete

Delete a snapshot and its associated files.

```bash  theme={null}
smolvm snapshot delete <snapshot_id> [--json]
```

<ParamField path="snapshot_id" type="string" required>
  The identifier of the snapshot to delete.
</ParamField>

<ParamField path="--json" type="flag">
  Output machine-readable JSON instead of human-friendly text.
</ParamField>

<Warning>
  Deletion is permanent. SmolVM removes the saved files for that snapshot, including any disk, VM state, and memory artifacts that snapshot type created.
</Warning>

**Example:**

```bash  theme={null}
smolvm snapshot delete before-deploy
```

### list

List all snapshots, optionally filtered by source VM.

```bash  theme={null}
smolvm snapshot list [--vm-id <vm_id>] [--json]
```

<ParamField path="--vm-id" type="string">
  Filter the list to show only snapshots created from this VM.
</ParamField>

<ParamField path="--json" type="flag">
  Output machine-readable JSON instead of human-friendly text.
</ParamField>

**Example:**

```bash  theme={null}
smolvm snapshot list
```

**Example output:**

```
  Snapshot ID        VM ID     Backend       Type   Restored   Created At
  before-deploy      my-vm     firecracker   full   No         2026-04-03T12:30:00
  pre-experiment     agent-1   firecracker   diff   Yes        2026-04-03T11:15:00

Total: 2 snapshot(s).
```

Filter by VM:

```bash  theme={null}
smolvm snapshot list --vm-id my-vm
```

## JSON output

All subcommands support `--json` for scripting and automation. The JSON response includes snapshot metadata such as `snapshot_id`, `vm_id`, `restored`, `created_at`, and file paths.

**Example:**

```bash  theme={null}
smolvm snapshot create my-vm --snapshot-id test-snap --json
```

```json  theme={null}
{
  "command": "snapshot.create",
  "exit_code": 0,
  "data": {
    "snapshot": {
      "snapshot_id": "test-snap",
      "vm_id": "my-vm",
      "snapshot_type": "full",
      "restored": false,
      "restored_vm_id": null,
      "created_at": "2026-04-03T12:30:00+00:00",
      "artifacts": {
        "state_path": "/home/user/.local/state/smolvm/snapshots/test-snap/vmstate.bin",
        "memory_path": "/home/user/.local/state/smolvm/snapshots/test-snap/mem.bin",
        "disk_path": "/home/user/.local/state/smolvm/snapshots/test-snap/disk.ext4"
      }
    }
  }
}
```

## Exit codes

| Code | Description |
| ---- | --- |
| `0` | Success |
| `1` | Error (snapshot not found, VM not running, etc.) |
| `2` | Usage error (missing subcommand or arguments) |
