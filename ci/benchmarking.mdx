Compare how quickly Celesto and GitHub Actions run the same work. Use these results as a starting point, then measure your own builds and costs.

## CPU and cache results — November 2, 2026

Three runs produced 36 successful jobs on runners with **4 vCPUs and 16 GiB RAM**: GitHub `ubuntu-24.04` and Celesto `celesto-large`. Both used Ubuntu 24.04.5 and Node.js 22.23.3.

The CPU test repeats the same calculation and counts iterations per second. Higher is better. For cache operations, lower time is better.

| Measurement (median) | GitHub Actions | Celesto Large | Difference |
| --- | ---: | ---: | --- |
| Single-core CPU, million iterations/s | 221.5 | 234.3 | Celesto +5.8% |
| Four-core CPU, million iterations/s | 827.7 | 924.1 | Celesto +11.6% |
| Restore a 512 MiB cache | 4.04 s | 3.60 s | Celesto 1.12× faster |
| Save a 512 MiB cache | 3.01 s | 6.09 s | GitHub 2.02× faster |

Medians use 18 CPU measurements, 9 successful cache restores, and 9 cache saves per provider. Every initial run missed the cache; every repeat hit it. Cache times include action overhead, transfer, compression, and extraction.

Celesto had higher median CPU throughput and faster cache restores in this test. GitHub saved the cache faster. These measurements cover individual operations, not complete job duration or billed runtime.

### Hardware and variation

GitHub assigned three processor models. Its EPYC 9V45 jobs were faster than Celesto's EPYC-Milan jobs; its EPYC 7763 and 9V74 jobs were slower. Matching CPU count and RAM does not match the underlying hardware.

Celesto cache restores ranged from 3.35–4.06 seconds; GitHub's ranged from 2.71–9.56 seconds. Celesto saves ranged from 4.46–28.47 seconds, including the slowest sample. One workflow ran alone; two ran concurrently. These three runs do not establish what caused the slower saves.

## Run the CPU and cache comparison

You need a repository connected to Celesto and credit eligible for Large. The Micro-only trial does not cover this runner.

<Steps>
  <Step title="Open the benchmark workflow">
    Open [Matched 4-core benchmark](https://github.com/CelestoAI/ci-benchmarks/actions/workflows/matched.yml). If you need write access, fork the repository and enable Actions in your fork.
  </Step>
  <Step title="Use a new cache name">
    Select **Run workflow** on `main`. Set `cache_namespace` to a unique name, such as `my-team-20261105-01`, for each experiment.
  </Step>
  <Step title="Check all 12 jobs">
    Expect six initial cache misses followed by six cache hits. Read each job's summary and download its raw timing artifact. The published results above pool three workflow runs.
  </Step>
</Steps>

See the [benchmark instructions](https://github.com/CelestoAI/ci-benchmarks/blob/32e8803259c5bb8a438218b15a65555cb58a189b/README.md#run-it-yourself) for setup and result collection.

## Compare your own workflow

- Match the commit, dependencies, CPU, RAM, and architecture.
- Measure fresh builds and cache reuse separately. Confirm the same tests pass.
- Repeat runs and compare medians, ranges, and failures.
- Include cache restore and save time. Saved computation can be outweighed by transfer time.
- Compare complete costs. Celesto bills computer runtime, including preparation and cleanup; queue time and provider allowances also affect your comparison.
