Use the Celesto CLI to give an agent a cloud computer, run commands, and delete the computer when its work is finished.

## Install and sign in

Use Python 3.11 or newer. The package includes the CLI and Python SDK:

```bash
pip install celesto
```

Open the [API key page](https://celesto.ai/api-key) and copy the default key shown there. It already has the organization access needed to create, inspect, use, and delete computers.

Save your key at the private prompt:

```bash
celesto auth login
celesto auth status
```

Agents can instead receive `CELESTO_API_KEY` in their process environment. Cloud commands use that key before the saved login. See [authentication](/cloud/authentication) for credential selection and storage.

## Make a first read-only call

```bash
celesto computer list --cloud --json
```

This lists cloud computers and creates nothing. An empty list is a successful result for a new workspace.

<Note>
  Select `--cloud` for cloud commands. Commands such as `create`, `list`, `info`, `exec`, `start`, `stop`, and `delete` otherwise operate on local computers. The older `get` and `run` commands are cloud-only aliases.
</Note>

## Create, use, and delete a computer

The free trial covers Micro. It allows two retained sandboxes per organization, including stopped and failed computers. Reuse a computer, delete one when finished, or add prepaid credit before creating more. The `trial_retained_sandbox_limit_reached` response includes the allowed `limit`; waiting does not free a retained slot. Other HTTP 429 errors can require different recovery steps.

Create one cloud computer:

```bash
celesto computer create --cloud --size micro
```

Copy the computer ID from the output. Replace `COMPUTER_ID` in the following commands with that ID:

```bash
celesto computer info COMPUTER_ID --cloud
celesto computer exec COMPUTER_ID --cloud -- uname -a
celesto computer delete COMPUTER_ID --cloud
```

The execution command prints Linux system information. Deleting the computer removes its files and frees its retained sandbox slot. To preserve files instead, stop it and start the same computer later:

```bash
celesto computer stop COMPUTER_ID --cloud
celesto computer start COMPUTER_ID --cloud
```

A stopped computer still counts toward the retained trial limit. If a create request times out, [inspect your computers](https://celesto.ai/computers) before repeating it: the request may already have created one. See [error handling](/cloud/errors) for uncertain outcomes.

## Cloud computer commands

| Command | Purpose |
|---|---|
| `celesto computer create --cloud [--size SIZE] [--template ID] [--no-internet]` | Create a cloud computer. |
| `celesto computer list --cloud [--limit N]` | List cloud computers. |
| `celesto computer info ID --cloud` | Inspect a computer. |
| `celesto computer exec ID --cloud [--start] [--timeout SECONDS] -- COMMAND ...` | Run a command on a running computer. `--start` requests startup but does not wait for readiness. |
| `celesto computer ssh ID --cloud` | Open an interactive terminal. |
| `celesto computer stop ID --cloud` | Stop a computer and preserve its files. |
| `celesto computer start ID --cloud` | Start a stopped computer. |
| `celesto computer delete ID --cloud` | Delete a computer. |

For an existing stopped computer, run `celesto computer start ID --cloud`, then inspect `celesto computer info ID --cloud` until its status is `running` before running commands or opening SSH.

Use `--size` for cloud CPU, memory, and disk allocations. See [resources](/cloud/features/resources) for sizes. Choose a template from the console's [Templates page](https://celesto.ai/templates), then pass its ID:

```bash
celesto computer create --cloud --template YOUR_TEMPLATE_ID
```

## Publish a port

Once an application is listening inside your computer, publish its port to receive a public HTTPS URL:

```bash
celesto computer port publish COMPUTER_ID --port 8000
celesto computer port list COMPUTER_ID --cloud
celesto computer port unpublish COMPUTER_ID --port 8000
```

`port publish` and `port unpublish` are cloud-only commands. `port list` requires `--cloud`. See [publish ports](/cloud/features/publish-ports) for supported ports and limits.

## Agent output

Use `--json` for a structured result. The response includes `ok`, `command`, `exit_code`, `data`, and `error`:

```bash
celesto computer create --cloud --size micro --json
celesto computer exec COMPUTER_ID --cloud --json -- uname -a
celesto computer delete COMPUTER_ID --cloud --json
```

For cloud creates, read the computer ID from `data.computer_id`. Keep this ID for cleanup. Check the command's exit code and error recovery message before continuing. Interactive SSH has no JSON mode.

## Update or remove your login

Run `celesto auth login` again to replace your saved key, or remove it:

```bash
celesto auth logout
```

Logging out removes the saved login. A `CELESTO_API_KEY` already set in an agent's environment remains a separate credential source.
