Celesto uses an API key to authorize requests for its organization. Get your key from the [API key page](https://celesto.ai/api-key). You can save the key once for CLI commands, set it in your environment for SDK code, or pass it directly when you create a computer client.

## Save your key for the CLI

For the `celesto` CLI, copy the default key shown on the [API key page](https://celesto.ai/api-key), then save it once:

```bash
celesto auth login
```

The command prompts for your API key and saves it in `~/.celesto/credentials` with owner-only file permissions. The key stays private; keep this file out of source control.

Manage the saved key with:

```bash
celesto auth status
celesto auth logout
```

<Tip>
  The saved login includes its API URL. Signing in again replaces that saved login. Use `CELESTO_API_KEY` explicitly when an agent needs a different key from the saved login.
</Tip>

## Choose credentials for cloud commands

Cloud computer commands use `CELESTO_API_KEY` from the current process first,
then the key saved by `celesto auth login`. Load a `.env` file into your shell
if you want it to supply this variable. Use `--cloud` to select cloud computers;
commands such as `celesto computer list` otherwise inspect local computers.

```bash
export CELESTO_API_KEY="your-api-key"
celesto computer list --cloud --json
```

The default key has the organization access needed for this read-only call and
for creating, using, and deleting computers.

## Check your saved login

`celesto auth status` validates the saved default key and reports its owner's
email and API URL. This command checks the saved login, while an SDK or cloud
command may use `CELESTO_API_KEY` instead.

Each key is bound to one organization. Use the matching organization in the
console when looking for computers created with that key.

## Scope SDK and REST integrations

The default key provides full access to its organization, including creating,
inspecting, using, and deleting computers. Integrations that already use a
scoped key need the corresponding permissions below.

| Permission | Actions |
|---|---|
| **See your computers** (`computers:read`) | Inspect computers and their state. |
| **Create, start, stop computers and run commands** (`computers:exec`) | Create, run, stop, resume, and connect to a computer. |
| **Delete computers** (`computers:admin`) | Delete computers. Required for automatic cleanup with `with CloudComputer()`. |

The key's owner also needs access to its organization. A valid key can still be
rejected when its permission or the owner's membership is missing; the
[error message](/cloud/errors) identifies the required change.

## Choose credentials for Python

`CloudComputer` checks these sources in order:

1. `api_key=` passed in code
2. `CELESTO_API_KEY` in the process environment
3. The key saved by `celesto auth login`

Load a `.env` file into your environment yourself if you use one; the Python
cloud client reads the process environment directly. An environment key takes
precedence over a successful saved CLI login.

## Use an environment variable

```bash
export CELESTO_API_KEY="your-api-key"
```

Create a computer, run a command, and delete it on exit:

```python auth.py
from celesto import CloudComputer


with CloudComputer() as computer:
    print(computer.run("uname -a").stdout)
```

## Pass the key in code

Pass `api_key` when you need to select credentials explicitly:

```python auth_explicit.py
import os

from celesto import CloudComputer


with CloudComputer(api_key=os.environ["CELESTO_API_KEY"]) as computer:
    print(computer.run("uname -a").stdout)
```

Both examples create a computer. Check the [quickstart](/cloud/quickstart) for
trial limits before running them.

`Computer.create()`, `Computer.get()`, `Computer.list()`, and `Computer.listTemplates()` resolve credentials automatically. The SDK checks these sources in order and uses the first one that has a value:

1. `token` or `apiKey` passed in the client config
2. `CELESTO_API_KEY` environment variable
3. `CELESTO_API_KEY` in a `.env` file in the current working directory

Set `CELESTO_API_KEY` before running the example so the selected key is explicit.

## Use an environment variable

```bash
export CELESTO_API_KEY="your-api-key"
```

List computers with the environment key:

```ts auth.ts
import { Computer } from "@celestoai/sdk";

const computers = await Computer.list();
console.log(computers.length);
```

## Use a local `.env` file

Create a `.env` file next to your entry point and add it to `.gitignore`:

```bash .env
CELESTO_API_KEY="your-api-key"
```

The SDK reads `.env` from `process.cwd()` when `CELESTO_API_KEY` is not already set in the shell, so the same `Computer.list()` call works without any extra setup.

## Share a key with CLI commands

Use `CELESTO_API_KEY` when the same agent needs both TypeScript and CLI access.
A login saved by the current Python CLI is separate from the older TypeScript
SDK credential-store integration. Setting the environment variable selects the
same key explicitly in both tools.

## Pass the key in code

Pass `token` when you need to select credentials explicitly. Explicit credentials take precedence over every other source:

```ts auth-explicit.ts
import { Computer } from "@celestoai/sdk";

const token = process.env.CELESTO_API_KEY;
if (!token) {
  throw new Error("Set CELESTO_API_KEY before running this script.");
}

const computers = await Computer.list({}, { token });
console.log(computers.length);
```

## Resolve credentials manually

The SDK exports the same resolution helpers it uses internally, so you can reuse them in your own tooling:

- `resolveCelestoApiKey(options?)` checks the environment and `.env`, then attempts the older CLI credential-store integration. Use an explicit environment key with the current Python CLI. It returns `undefined` if no compatible source is available.
- `resolveClientConfig(config?, options?)` returns a `ClientConfig` with `token` populated, preserving any explicit `token` or `apiKey` you already passed. It throws `CelestoError` with `MISSING_CREDENTIALS_MESSAGE` when no credentials are available.

```ts resolve.ts
import { resolveCelestoApiKey, resolveClientConfig } from "@celestoai/sdk";

const apiKey = await resolveCelestoApiKey();
console.log(apiKey ? "Found a Celesto API key" : "No credentials configured");

const config = await resolveClientConfig();
console.log(`Using token ending in ${config.token?.slice(-4)}`);
```
